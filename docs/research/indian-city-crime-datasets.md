# Indian City Crime Datasets — Research Note

> **STATUS SUPERSEDED 2026-09-10: Indian options REJECTED for main pipeline. Project locked to Chicago 2019-2024 (data.cityofchicago.org Crimes 2001-Present slice) for HDBSCAN/ML. Keep this note only as viva proof (21 primary sources: no official Indian incident-level lat/long found).**

- **Date:** 2026-09-10 (all sources accessed this date unless noted)
- **Question:** Find one reliable, versioned crime dataset for ONE Indian city suitable for historical hotspot analysis + HDBSCAN, satisfying the plan.md data contract (crime category, date/time, city/area, WGS84 lat/long, source-row ID) and the AGENTS.md data rules.
- **Method:** Primary sources only — official portals (data.gov.in, ncrb.gov.in, mospi.gov.in), first-party police sources via OpenCity mirrors of official releases, source repos (raw CSV bytes verified by download), licence pages. Every factual claim is cited in §6. Items that could not be verified are marked **UNVERIFIED**.

## TL;DR recommendation

1. **Lock Bengaluru as the study city**, using the **Bengaluru City Police (BCP) 2021–2023 aggregates via OpenCity** (source: `bcp.karnataka.gov.in`) cross-checked against **NCRB Crime in India city-wise tables for Bengaluru** — with a **documented area-level spatial fallback** (police-station points/jurisdictions), because **no official incident-level dataset with lat/long was found for any Indian city** on any primary portal checked.
2. **Do not use the GitHub/Kaggle "incident-level" mirrors** (chetanp9, gyanendra23, navneet-nmk, Kaggle NCRB copies): the two row-level CSVs were byte-verified to contain **no latitude/longitude**, cite **no original source**, show synthetic-looking patterns, and therefore fail the data contract while adding licence/provenance risk.

**Negative finding (important):** across data.gov.in (crime-keyword catalogue, NCRB holdings, Pune FIR resource), ncrb.gov.in, BCP/KSP releases, TN Police CCTNS reviews, and Mumbai Police releases, **every official resource found is aggregate counts (annual; monthly at best) — none publishes incident-level rows with latitude/longitude**. data.gov.in's crime holdings are NCRB annual tables (e.g. Crime in India 2019: 292 CSV resources, annual granularity) plus jar-level items like Thane Rural registrations and year-wise cyber-scam counts. No Indian city police portal found here publishes an open incident-level geocoded feed (contrast US portals, which do — out of scope).

## 3. Limitations / ethics statement (per AGENTS.md)

- **Reported-crime bias only.** All sources are police-recorded data (FIR → SCRB/CID → NCRB pipeline; BCP press releases). MoSPI and NCRB's own methodology note large non-reporting, Principal-Offence-Rule undercounting (one FIR = one head), and that NCRB compiles but does not authenticate state data. Frame every result as "reported crime", never as true crime incidence.
- **No individual prediction.** Outputs are aggregated historical hotspots (station areas / grid cells × periods). Never present clusters as predictions of individual criminality or as a basis for policing people.
- **Aggregation + suppression.** Publish only aggregated hotspot polygons/cells; suppress any unit with fewer than the configured minimum incidents (set `min_incidents` in preprocessing config; suggested start: 10–15 given annual granularity).
- **No PII.** None of A–D contains personal data; the GODL licence additionally exempts personal information. Keep victim-demographic columns (age/gender in mirror E) **out** of the analysis dataset even if a row-level source is later adopted.
- **Coordinate honesty.** Until an incident-geocoded source is locked, every map must be labelled "station-area aggregation, not incident locations"; HDBSCAN `eps`/distance thresholds apply to station-point geometry.
- **Comparability warning.** NCRB explicitly cautions against naive state/UT comparisons; the same applies across cities and across IPC→BNS (2024+) classification changes.
